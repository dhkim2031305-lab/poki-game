# 시험 계획 — 개발 작업15 "한국 완성 샘플" (준비 2026-11-28)

- 요청: 팀장 2026-11-28
- 근거: `teams/3-개발/review-4/polish-2026-11-28/codex-진단.md` 4절 "완성 판정"
- 대상: 거북선(한국1)·천자총통(한국2) 고도화, 2번 스킬 컷인·크기·느려짐
- 시작 조건: 개발팀이 작업15 커밋을 알려 오면 시작해요. 그 전에는 이 계획만 둬요.

## 통과 기준 (한 줄)
**외침과 흔들림을 끈 상태에서** 아이폰 가로 화면(844×390) 캡처만 보고 세 가지를 짚을 수 있어야 해요.
1. **어디서 발동했는지**: 거북선 뱃머리가 나온 자리, 화포 포구
2. **어느 적이 맞았는지**: 맞은 적의 앞면이나 접촉점에 신호가 보여요
3. **누가 빗나갔는지**: 안 맞은 적에게는 신호가 없어요

밝기와 그림 크기는 그다음에 봐요.

## 환경
| 항목 | 값 |
|---|---|
| 화면 | 844×390 (아이폰 가로), 보조로 667×375 한 번 |
| 그리기 | 2D(`?render=2d`)로 판정해요. 3D는 swiftshader 캡처로 같은 장면을 한 번 확인해요(이 서버는 GPU가 없음) |
| 입력 | 터치 컨텍스트(`hasTouch`)로 해요. 2번 스킬은 끌어 놓기와 톡을 둘 다 써요. PC 키(L·;)는 보조로만 써요 |
| 흔들림 끔 | 설정 `shake` = 꺼짐. 이 설정은 `layerFx()`도 같이 꺼서 화면 번쩍·히트스톱도 꺼져요. 꺼진 상태로 판정하고, 켠 상태는 비교용으로 따로 찍어요 |
| 외침 끔 | 게임에 외침 끄기 설정이 없어요. 시험 코드에서 프레임마다 `G.msgs`의 외침(shout)을 지워 흉내 내요. 작업15에 설정이 생기면 그 설정을 써요 |
| 시간 | rAF를 손으로 넘겨요(1/60초). 0.05초 간격으로 캡처하는 기존 방식(`skillframes.js`)을 써요 |

## 장면 표 (스킬마다 8장면 × 2스킬 = 16)
| # | 거리 | 적 배치 | 볼 것 |
|---|---|---|---|
| 1 | 근거리(목표 120px) | 헛치기: 경로·범위 밖에 1마리 | 접촉 신호가 **안 나와야** 해요. 발동 자리는 보여야 해요 |
| 2 | 근거리 | 1마리 정면 | 그 적 앞면에 접촉 신호가 나와요. 적 반응(밀림 방향)도 봐요 |
| 3 | 근거리 | 여러 마리(경로·범위 안 3 + 밖 2) | 맞은 3마리에만 신호가 나와요. 밖 2마리와 구분돼요 |
| 4 | 근거리 | 보스 1 + 졸개 2 | 보스에도 명중 신호가 나와요. 보스는 짧은 움찔이에요 |
| 5~8 | 원거리(목표 300px 이상, 화면 끝 근처) | 1~4와 같아요 | 같아요. 화포는 포구 → 비행 → 착탄이 끊기지 않는지 봐요 |

- 천자총통은 6발을 따로 봐요. 1~5발(둘레)과 6발(가운데)의 강약 차이, **6번째 탄이 끝까지 날아가 보이는지**를 봐요. 진단 5번에 따르면 마지막 탄 비행과 연출 객체 만료가 겹쳐요.
- 거북선은 뱃머리가 **장수 앞에** 있는지, 장수 발치에 겹치지 않는지 봐요. 첫 접촉 순간 신호가 장수 자리가 아니라 **적 자리**에 나오는지도 봐요.

## 2번 스킬 컷인·크기·느려짐
| 볼 것 | 재는 법 | 기준 |
|---|---|---|
| 컷인 | 나오는 시각과 길이(프레임), 화면에서 차지하는 영역 | 컷인이 발동 자리와 맞은 적을 가리지 않아야 해요 (캡처로 가림 여부를 봐요) |
| 크기 | 화포·포탄·거북선의 그린 폭(drawImage 기록, `job11.js` 방식) | 개발팀이 정한 수치와 같아야 해요 |
| 느려짐 | 느려지는 배율과 길이를 시험 코드로 기록 | 실제 시간 기준으로 피해 시각·횟수·총 피해가 느려짐 전과 같은지 봐요(`cannon6.js`, `dmgtime.js`). 느려지는 동안 입력이 사라지지 않는지(이동·무적 버튼) 봐요 |

## 회귀 (짧게)
- `cannon6.js`: 0.3초 간격 6발, ×0.2/×0.4, 가운데 ×1.4. 화포가 **장수 옆(조금 뒤)**에 서는지도 봐요(기획 0cf542e). 지금 코드는 목표 28px 앞이에요.
- `castinv.js 8080 14`: 무적은 세우는 동안만, 거북선은 시전 동안만이에요.
- `skillprobe.js … 14,3,7 30|50 2`: 천자총통 vs 미국2·호주2 처치 수. 3차 ÷5·÷6이 반영됐으면 기획팀이 부탁한 비교를 같이 해요.
- `job11.js 8080 14`: 코드 도형 0(허용 예외만), 에러 0이에요.

## 판정 방법
1. 장면마다 0.05초 간격 캡처에서 **맞는 순간 한 장**과 **0.2초 뒤 한 장**을 골라 표에 붙여요(외침·흔들림 끔).
2. 같은 장면을 흔들림 켬으로 한 장 더 찍어 비교해요.
3. 캡처에 정답 표시 없이 먼저 Claude가 "발동 자리·맞은 적·빗나간 적"을 짚어요. 그다음 시험 코드의 실제 피해 기록과 대조해요.
   - 틀리게 짚은 장면 = 읽히지 않는 장면이에요.
   - 사용자가 원하면 GPT에게도 정답 없이 보여 두 번째 의견을 받아요.
4. 결과 표: 장면 16개 × (발동 자리 / 맞은 적 / 빗나간 적) ✅·❌ + 캡처 파일 이름
5. 실제 폰 손맛(진동·소리 박자)은 사람이 확인해야 한다고 적어요.
